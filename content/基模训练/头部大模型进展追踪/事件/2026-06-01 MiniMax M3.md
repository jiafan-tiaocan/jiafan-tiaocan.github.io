# MiniMax M3

> [!summary] 当前判断
> MiniMax M3 的可辩护增量是把**稀疏注意力、1M context、原生图像/视频、电脑操作和开放权重**打包为一个生产模型。它在能力上不是绝对第一，但可能在“开放多模态 Agent 的任务级成本”上形成更有意义的工作点。

## 发生了什么

MiniMax 于 2026-06-01 发布 M3。官方称 M3 使用 MiniMax Sparse Attention（MSA），支持 1M context、图像与视频输入、电脑操作，并重点优化 coding 与 agentic work。随后发布 MSA 论文、kernel 和开放权重。

## 相对 M2.7 的真实增量

- **新注意力架构：** MSA 先以轻量 Index Branch 为每个 GQA 组选择 KV blocks，再让 Main Branch 执行精确 block-sparse attention。
- **长上下文计算下降：** 官方在 1M context 声称每 token attention compute 降至 M2 的约 1/20，并报告大幅 prefill/decode 加速；论文给出 H800 上的单独测量条件。
- **原生多模态：** 图像、视频与文本进入同一模型，不再只是文本 Agent。
- **互动式 Agent 训练/评测：** 官方描述了用户模拟器，用连续澄清、反馈纠正、任务切换和项目迭代逼近真实开发协作。

## 外部反馈

[Artificial Analysis](https://artificialanalysis.ai/models/minimax-m3) 给出的快照为 Intelligence Index 44、约 82.2 output tok/s、1M context；每百万 token 输入价格为 0.30 美元、输出为 1.20 美元。它认为 M3 在同体量开放权重模型中能力较强、速度高于平均、价格合理且输出相对简洁。

与 Kimi K3 或 GLM-5.2 相比，M3 的独立综合能力分数较低；但它的价格、吞吐、原生视频输入和较少输出 token 构成不同的产品位置。舆论中的“前沿”应理解为特定 coding/agent/multimodal 组合，而不是所有能力维度的总冠军。

## 代价与边界

- MSA 的 1M 加速主要来自官方论文与自报 kernel 测量，需要不同 GPU、batch、长度与真实服务负载下复现。
- 最大窗口不等于 1M 范围内无损召回。
- MiniMax Community License 对高收入商业使用有额外通知或授权条件。
- 428B total / 23B active 仍不是普通消费级本地模型；量化后显存和长上下文 KV 状态需单独核算。
- 官方发布 benchmark 与开放后独立结果的 harness 可能不同。

## 下一步验证

首先在 128K、512K、1M 三档复现 MSA 的 prefill、decode、峰值显存和有效召回；再用同一电脑操作/代码 Agent harness 比较 M2.7、M3 和其他开放模型，记录视频输入后的任务成功率与 token 成本。
